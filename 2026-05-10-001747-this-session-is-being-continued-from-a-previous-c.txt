⏺ Good stopping point to assess coverage. The MSIR now handles:
  - All arithmetic/compare/logic ops, control flow (IF/ELSIF, WHILE, LOOP/EXIT)

  - Records, fixed arrays, open arrays, VAR/READONLY formals
  - Globals (traced + untraced), gc_ref, enums, NIL, TEXT/object stubs

  What's still missing that matters for real programs:

  1. FOR loops — FOR i := lo TO hi DO / BY step — very common, requires a
  preheader+body+exit block pattern similar to WHILE
  2. CASE statements — CASE x OF | a => ... | b => ... — maps cleanly to a
  switch/branch chain in SSA
  3. DIV / MOD — x DIV y, x MOD y — common, DivExpr.m3 / ModExpr.m3 need
  compileMSIR
  4. AND / OR short-circuit — AndExpr, OrExpr need lazy-evaluation block
  structure
  5. LLVM emitter — wiring MSIR → LLVM IR is the destination; the IR is now rich
   enough to start a skeleton MSIRToLLVM.m3

  My recommendation: FOR + CASE + DIV/MOD next, then pivot to the LLVM emitter.
  FOR and CASE are the most common missing constructs in real M3 code; DIV/MOD
  is two files and trivial. After those three, the MSIR is complete enough to
  make an LLVM emitter meaningful.

  Or if you want to jump straight to the LLVM layer, the existing MSIR is
  already enough for a skeleton — integers, structs, arrays, calls, branches,
  globals all translate directly.
